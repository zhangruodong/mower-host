# 功能

这块面板现在能干什么。每条都写了实现在哪个函数，改的时候照着找。

---

## 一、主界面（7 个按钮）

| 按钮 | 函数 | 干什么 |
|---|---|---|
| 整机自检 | `start_self_test()` :1144 | 发 `CMD=5`，固件置 `selftest_trigger = 1` 开始跑自检；界面记日志，`_selftest_done()` 收尾 |
| 开始割草 | `start_mow()` :1155 | 弹窗选地图（只记日志，不加载）+ 开始录像 + 打开绿色检测。**不发刀片指令**，见 [移除记录.md](移除记录.md) |
| 雷达跟随 | `toggle_follow()` :1188 | 起 `core/lidar_follower.py`：订阅 `/scan`、发布 `/cmd_vel`，**只在有目标时才发速度**。按钮变「停止跟随」 |
| 自动回充 | `start_dock()` :1208 | 跑 `DockController`：舵机在 600 ↔ 2400 µs 之间扫，摄像头看到 AprilTag 就停下 |
| 手动控制 | `show_manual()` | 翻到手动页（见第四节） |
| 紧急停止 | `stop_all()` | 停掉当前所有任务，发 `CMD=7` 锁存急停 |
| 解除急停 | `release_estop()` :1141 | 发 `CMD=8`。急停是锁存的，只有这条命令或复位能解 |

主界面还有状态栏、发送/接收日志（各自可清空）、以及进入 SLAM 页和设置页的入口。

## 二、设置页

**切换外设** —— 三选一，存进 `~/.割草机_config.json` 的 `hw_mode`：

| 选项 | 值 | 含义 |
|---|:---:|---|
| 摄像头(普通) | 0 | 只用 USB 摄像头 |
| 双目+激光雷达 | 1 | 深度相机 + 雷达 |
| 自动识别 | 2 | 让 `core/hw_detector.py` 自己认 |

自动识别按 **USB 芯片 ID** 认设备（RealSense D435/D415、Orbbec Astra 系列、RPLidar C1/A1），
不看插在哪个口。

**清除缓存** —— 清除视频（进视频页）/ 清除配置文件。

**速度显示** —— 三种：

- 仅显示速度：`ui/speed_gauge.py` 画仪表盘
- 记录并显示：仪表盘 + 曲线记录
- 波形显示：`ui/waveform_widget.py`，pyqtgraph 滚动波形

## 三、SLAM 建图与导航

「SLAM 建图」页有五颗按钮。

**开始建图** `start_mapping()` —— 起 SLAM，建图期间**先把我们的底盘桥停掉**（串口同一时刻只能
一个进程开）。三套算法可选，对应树莓派工作空间里装好的包名：

| 选项 | launch |
|---|---|
| slam_toolbox | `slam_toolbox online_async_launch.py` |
| gmapping | `slam_gmapping slam_gmapping.launch.py` |
| cartographer | `cartographer_ros cartographer.launch.py` |

建图时会另起一个 `rviz2 -d RVIZ_CFG`，**地图是在那个窗口里看的**（面板里不画地图，
原因见第十节 10.2）。

**保存地图** `_save_map()` —— 后台跑 `map_saver_cli`，写进 `MAP_DIR`，文件名
`mymap_YYYYmmdd_HHMMSS`。

**Nav2 导航** `start_nav()` —— 点一下启动、再点停止。用的是 `nav2_bringup bringup_launch.py`。
停止时会 `pkill` 掉 `nav2_bringup` / `rviz2` / 雷达驱动，并调 `/stop_motor` 服务停电机。

**停止建图** `_stop_slam()` —— 停 SLAM，并把底盘桥拉回来接管串口。

**地图库** —— 见下一节。

## 四、地图库

缩略图卡片式列表，五个操作：

- **刷新** `_refresh_gallery()`
- **rviz2 查看** `_open_map_rviz()` —— 用 `RVIZ_CFG` 那份配置打开
- **图片查看** `_open_map_ppm()` —— 直接看 `map_saver_cli` 出的 ppm
- **重命名** `_rename_map()` / **删除** `_delete_map()` —— 可多选

## 五、手动控制

键盘直接开：**方向键**或 **WASD**（`_manual_keys()` :1085）。

- `_manual_tick()` **10 Hz 重发**速度帧
- 松键立即归零（`_manual_set(0, 0)`）
- 速度是车体系：↑↓ 走 `Vx`，←→ 走 `Vz`，`Vy` 恒 0

10 Hz 这个频率是照桥的 **0.5 秒看门狗**定的——面板万一崩了，桥半秒后自己发零速停车。

## 六、摄像头与录像

`ui/camera_widget.py`：

- 实时画面
- **AprilTag 检测**（`core/tag_detector.py`，`DICT_APRILTAG_36H11`，ID 0）—— 回充靠它对准
- **绿色检测** —— 割草时才打开
- 录像写进 `~/Videos/割草机`

**视频页**：列表、播放、按时间排序、全选、删除所选。

## 七、底盘桥（`bridge/`，ROS2 包 `mower_bridge`）

节点 `chassis_bridge`，**替掉底盘原来那套节点**——装了它就不需要任何厂商 ROS 包
（原因见 [架构.md](架构.md)）。

| 方向 | 话题 | 类型 |
|---|---|---|
| 订 | `/cmd_vel` | `geometry_msgs/Twist` |
| 订 | `/servo_cmd` | `std_msgs/Int16` |
| 订 | `/selftest_cmd` | `std_msgs/Empty` |
| 订 | `/emergency_stop` | `std_msgs/Empty` |
| 订 | `/estop_release` | `std_msgs/Empty` |
| 发 | `/odom` | `nav_msgs/Odometry` |
| 发 | `/imu/data_raw` | `sensor_msgs/Imu` |
| 发 | `/PowerVoltage` | `std_msgs/Float32` |

另外：

- **0.5 秒看门狗**：`/cmd_vel` 超时没新指令就补一帧零速度，节点退出前也补一帧
- **Mahony 互补滤波**出四元数 —— EKF 的 `imu0_config` 里 `yaw = true`，姿态必须真算
- 不发 TF，`odom_combined → base_footprint` 由外部 `robot_localization` 出
- 参数：`port` `baud` `odom_*_scale` `cmd_vel_timeout` `frame_id_*`
- 不解析 19 字节超声波帧和 8 字节回充帧（割草机没这两个硬件）

## 八、协议层

- `bridge/mower_bridge/protocol.py` —— **权威实现**，收发都有
- `core/protocol.py` —— 只组帧，离线自检和没装 ROS 时用；**改协议两边一起改**

两个自检随时能跑，不需要硬件：

```bash
python3 core/protocol.py                # 组帧字节序列自检
python3 bridge/test/test_protocol.py    # 组帧 / 解析 / 重同步 / Mahony
```

完整的帧格式、每个 CMD 干什么、上电静默期，见 [协议.md](协议.md)。

## 十、还没做的

上面九节是「有什么」，这里是**断在哪一行、要接什么才能算完**。

### 10.1 自动回充：只有舵机扫掠

**现在能跑的**：`start_dock()` → `DockController.start()` → 状态 `SWEEPING`，起一个 30 ms
定时器，`_tick()` 每跳把 `_servo_pos` 挪 8 µs，在 600 ↔ 2400 之间来回，到头发方向翻转。
摄像头侧 `on_tag_seen` → `tag_detected()` → 置 `tag_seen = True`，状态转 `VERIFYING`，
调 `on_tag_found()`，状态栏显示「对准中...」。

**然后就没有然后了**：

- `_tick()` **只在 `SWEEPING` 分支里干活**——状态一进 `VERIFYING`，舵机停住，不再有任何输出
- `on_done` **全文件没有任何地方调用**，界面 `:1211` 挂的 `_on_dock_done()`（「对接完成」）
  是死代码
- 整个过程**没发过一个速度指令**，底盘不动，只有云台在扫

实际行为：**按「自动回充」→ 舵机左右扫 → 看见 AprilTag → 停下来 → 卡住。**
不会撞、不会跑，但也不会完成。

**要接什么**：底盘侧命令是现成的，协议定了、桥里常量也在
（`CMD_RECHARGE` / `CMD_DOCK`），**只是没人发**：

| CMD | 固件行为 | 用途 |
|:---:|---|---|
| 1 / 2 | 写 `charger.Up_MoveX/Y/Z`，并置 `AllowRecharge = 1` | 远距离开回充电桩 |
| 3 | 写 `charger.Dock_MoveX/Y/Z`，**不碰** `AllowRecharge` | 近距离红外对接微调 |

缺的环节：`VERIFYING` 之后做**对齐验证**（Tag 在正中吗？够近吗？）→ CMD=3 **横向微调** →
判断要不要**旋转** → CMD=1/2 **进桩/退桩** → 读电压**确认在充电** → **失败重试**（扫几轮
没找到就放弃，别无限扫）。

⚠️ 现在这条路径**不会让车动**，所以不存在失控风险。**一旦接上 CMD=1/2/3，必须先把急停
那条链路测通**——见 [DISCLAIMER.md](../DISCLAIMER.md) 第三节。

### 10.2 面板里那块地图窗口没接上

**先说清楚：建图是能用的。** `start_mapping()` 选完算法就 `ros2 launch` 起 SLAM，再另起一个
`rviz2 -d RVIZ_CFG`（`ui/main_window.py:706-715`），地图直接在 **rviz2 窗口**里看。保存地图、
Nav2 导航也都正常。

没接上的是**面板自己内嵌的那块地图**——`ui/mapping_widget.py` 的 `MappingWidget` 是写好的：
pyqtgraph 栅格、障碍物颜色表、`feed_map()` 接 `/map`、`feed_speed()` 用速度做航迹推算。
但搜遍全工程**一处 `MappingWidget(` 都没有**，这个类从来没被实例化过。

数据链路前半段是通的：`core/ros2_client.py:81` 订阅 `/map` → `:99` 发成 `map_updated` 信号 →
`main.py:55` 接到 `window._mapping_widget.feed_map(...)`。断在守卫那句
`if ... and window._mapping_widget else None`——`_mapping_widget` 恒为 `None`，所以这个 lambda
每次都是空操作。

| 位置 | 现状 |
|---|---|
| `ui/main_window.py:3` | 导入了 `MappingWidget`，没用过 |
| `ui/main_window.py:43` | `self._mapping_widget = None`，之后再没赋过真值 |
| `main.py:55` | 信号连接是**空操作**，守卫恒假 |
| `ui/main_window.py:116` | `_feed_mapping()` 里的 `_mapping_widget` 同样恒 `None` |
| `ui/main_window.py:1230` | `stop_all()` 里那句 `self._mapping_widget.close()` 永远走不到 |

**想把这块补上的话**：在建图页实例化 `MappingWidget` 塞进 `stack_layout`，把
`self._mapping_widget` 指过去；`start_mapping()` 里建、`_stop_slam()` / `stop_all()` 里
`close()` 并置回 `None`。信号和 `_feed_mapping()` 都是现成的，接上就能画。

> 现在这样也不影响用：rviz2 那张图信息更全，面板这块算锦上添花。
